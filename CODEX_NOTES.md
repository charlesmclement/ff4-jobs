# Notes for Codex: scripted-run (TAS) bugs and changes

Running log kept by Claude while working on the TAS. Newest last. "Live" means
the user ran it in the game. Everything else is compile-only or static
analysis. See also `CLAUDE_HANDOFF.txt` and `docs/TAS-SEGMENT-2.md`.

## How we fix bugs (user's standing workflow)

1. The user presses **F10** (stop) and **quicksaves** where the run went wrong.
2. Fix it, rebuild with `tas/build.sh --build-only`, and log it below.
3. The user closes the game, opens **FF4 TAS: Segment 2**
   (`tas.py launch --resume`), and loads the quicksave. The route picks the
   step from the map and story flags.

Never make the user restart from New Game for a fix. The running game keeps
whatever build it launched with, so always say which build is live.

## Bugs found and fixed (Nov 1 2026)

1. **Stuck on the controls help after the opening (live fixed).** Phase
   `FieldHelp` is the native help/pause window. The opening event ends with
   `ShowHelpAndExit`, which opens it with `FieldHelpManager.IsOpenHelp` set. In
   that mode `UpdateDisplayHelp` ignores Cancel and never reads Confirm; only
   `Key.Start` closes it. The first fix (pulse Back) failed live. The engine now
   pulses Start, then Back (`RouteEngine.Tick`).
2. **Door animations aborted the route (live fixed).** Door opening is the
   SubScene state `Gimmick` (11), which no step allowed. All route steps now
   allow `Gimmick`, and no input is sent during it.
3. **Focus loss killed the run (live fixed).** Focus loss now pauses: input is
   released, step timers freeze, and the run resumes 30 frames after refocus.
   `status.json` shows `paused`.
4. **No path on the overworld (live fixed).** `MapRouteSearcher` returns
   nothing on `map_10010`: its collision group is empty, and walkability
   comes from the `GroundAttribute` grid plus master `transportation_group`
   (row 1 = on foot; attribute N maps to column typeN). Steps now take
   `waypoints`, generated by `tas/plan_path.py`. Navigation also falls back to
   neighbour/closer-cell legs, a final step into trigger tiles, and direct
   steering.
5. **Mist Cave warning picked "No" forever (live fixed).** The `Select` in
   `sc_e_0007` defaults to index 1. Steps take `choice`. The plugin reads
   `MessageSelectWindowManager.Instance.IsOpen()` and
   `controller.selectCursor.Index`, and the engine steers to the option.
6. **Audit y-coordinates were off by one (fixed, tool only).** Tiled tile
   objects (with a `gid`) are anchored at their bottom edge, so cell y is
   `y/16 - 1`. Verified: arrival point 1 = (107,145), matching the live trace.
   Any code that reads entity cells must apply this.

## Features added

* F8 TAS speed boost (default 3x, env `FF4JOBS_TAS_SPEED`). It owns only the
  `timeScale` it set and coexists with the Jobs LT/F6 fast-forward (live OK).
* Run timer: the TAS time is the sum of scaled `deltaTime` (game time), so the
  boost can't shorten it. Wall clock is shown for reference. OnGUI overlay;
  `status.json` has `gameSeconds` and `elapsedSeconds` (live OK).
* Navigation arrival tolerance widens with the observed per-frame stride, for
  boosted movement.
* Tools: `tas/extract_maps.py`, `tas/map_links.py`, `tas/plan_path.py`, `tas/audit_items.py`.

7. **Stuck on the Jobs+ "Job unlocked!" popup (fixed, compile-only).** At flag 7
   Jobs+ opens a CommonPopup over the field during the Player phase and blocks
   `FieldMap.UpdatePlayerStatePlay`. The navigate step only sent directions,
   so it failed as "Movement stalled at (108,106)". The plugin now sets
   `Snapshot.Modal` from `PopupManager.Instance.Filter.activeInHierarchy` (the
   same modal test as Jobs fast-forward), resets navigation while it's up, and
   the engine pulses Confirm for every step kind outside battle. Jobs'
   `MenuInput` reads `InputListener`, so the injected Confirm reaches it.

8. **Kaipo: "no native route", walking up and down (fixed, compile-only).**
   Collision layer index = Bottom 0, Ground 1, Upper 2 (confirmed from trace
   cell z: Kaipo 2, overworld/Mist 1, Baron/Mist Cave 0). Kaipo walks on
   UpperCollision, so goals written with layer 0 never planned, and the
   direct-steering fallback rotated directions. Segment 2 goal layers were
   recomputed from each map's collision (first free layer at the goal). The
   navigator now also retries the goal on the player's own layer, and arrival
   compares world x/y only.
   **Rule for new routes:** set `layer` from the map's collision file (that
   index mapping), never assume 0.

9. **Titan wipe stopped the run (fixed, compile-only).** At Mist the
   scripted Titan quake kills the whole party, and the event then continues
   (map 319). `BattlePilot` failed on "all party HP 0". It now waits instead;
   a real game over changes the phase to GotoTitle, which no step allows, so
   the engine still stops on genuine defeats.

10. **Battle choices reworked (compile-only), from live feedback.** Kain used
    the last Potion in the scripted Titan fight, Cecil wasn't being healed,
    zombies were attacked, and Tellah wasted turns on Attack. `BattlePilot.Decide`
    now runs once per turn, in this order: scripted fights (enemy 207, or any
    enemy with max HP ≥ 30000) just Attack; Phoenix Down on the dead; heal
    under 50% HP, Cecil first (White Magic Cure, ability 6, 3 MP; Potion if
    there's no MP; Tellah prefers Potions); Cure on undead (species 4) for
    non-Tellah casters; the route's battle plan; Attack the weakest enemy
    (target cycling, one lap at most). Defend (2) is allowed in plans.
11. **Watery Pass camp is taken, not skipped.** `sc_e_0012_2` restores HP and
    MP (RecoveryHP/RecoveryMP) for free, with no Tent. Before the camp Tellah
    plan = Thunder while MP ≥ 5, else Defend. After it = Thunder only while
    MP ≥ 45, else Defend. Octomammoth = Thunder, then Recall; Cecil Darkness
    above 50% HP.
12. **Speed boost default is 6x** (still F8 toggle, `FF4JOBS_TAS_SPEED`). It
    is `Time.timeScale`, so battles should speed up as well. That's
    unconfirmed: if FF4 PR's ATB ignores timeScale, battles won't speed up.

13. **Tellah stuck on Osmose (fixed, compile-only).** In the battle ability
    list `selectCursorIndex` never changes, so the stride logic kept pressing
    Right and the cursor ran to the last spell. `SelectAbility` now reads the
    index from `selectCursorList[0].Index` (`Last.UI.Cursor`), prefers the
    on-screen rows' `contentList[i].Data.Ability.Id`, and blocks the rule for
    the battle after 3 moves that don't move the cursor (falls back to the
    next rule, e.g. Defend).

14. **Launcher died silently waiting for a resume (fixed live).** The runner
    replaces `status.json` every 0.1 s, so `tas.py` could read it mid-replace
    (`FileNotFoundError`). That aborted `launch --resume`, which then sat at
    "Press Enter". `state()` now retries for up to 1 s. The route was started
    with `tas.py start <route> --from-step 0` (auto step), which is safe
    because a run waits, paused, until the game has focus.

15. **MP policy (user: "waste of mana").** Thunder is only for Octomammoth.
    Random encounters: Tellah Defends. When undead are present, any caster
    uses White Magic Cure on all enemies (PageDown/PageUp toggles EnemyAll,
    target state 4, in `EnemysUpdate`), or on the single undead. New
    `BattleRule.ReserveMp` is MP the character never spends outside its rules
    (Tellah keeps 40 after the camp, 0 before it since the camp refills).

16. **Elemental spell choice (compile-only).** Live, the old build cast
    single-target Thunder on everything: 3 Thunders on 3 fish, Thunder on
    zombies and on Red Mousse (weak to fire). Routes now carry `weaknesses`
    (monster id -> [1 fire, 2 ice, 3 lightning]), generated by
    `tas/weaknesses.py` from monster.resistance_attribute -> attribute_group
    with type 1 or 401. Rule `byWeakness` picks the spell for the most common
    weakness on screen and casts it on all when two or more share it. With
    `minEnemies: 3` and `orTough` it fires only for groups of 3 or more, or
    when an enemy has defense >= 200 (mousse/jelly, 254). Otherwise Tellah
    Defends. Undead still get Cure (on all if there are several) first.
    **Process lesson:** each live complaint came from the user watching an
    older build. Batch fixes, rebuild once, and state which build is live.

17. **Chest pickups from the community route.** New `Condition.TreasureFlag`.
    The plugin reads `DataStorage.Category.kTreasureFlag1` for the step's
    flag. The segment 2 route now opens the Ether (165), Shadowblade (169),
    Hades Armor and Hermes Sandals (172): navigate beside the chest, then
    interact facing it. A summary of the community notes, plus everything
    that still needs a menu/shop driver, is in docs/TAS-SEGMENT-2.md.

18. **Darkness is an HP-costing AoE wave in PR** (ability 165, battle range
    4 = all enemies; the user confirmed it isn't a stance). The community
    strat is one Darkness, then Attack, with another after the Mist Dragon's
    mist phase. Rules gained `OncePerBattle` (re-armed when the Mist Dragon
    enters mist) and `BossOnly` (monster master `Boss != 0`). Mist Dragon and
    Octomammoth plans: Cecil Darkness once (boss only), then Attack.

19. **Battle knowledge base and fight log (compile-only).**
    `tas/battle_db.py` builds `research/tas-battle/battle.json` from master
    data (264 monsters: HP, defense, magic defense, weaknesses from
    attribute_group types 1/401, raw resist codes, undead = species 4, boss,
    steals, maps; 446 spells/abilities: MP, element, target range), plus
    `monsters.md` and `spells.md` for humans. `tas.py` copies battle.json
    into the session on every start, and `BattleDb` loads it. The pilot takes
    weaknesses from it (falling back to Route.Weaknesses) and skips spell
    rules the actor can't afford. Each frame `Snapshot.Battle` =
    "enemies with HP | who: decision (reason)" goes into status.json and the
    trace. `tas/battle_log.py [trace]` prints fights for review and coaching.

20. **Cecil cycled the enemy cursor forever (fixed, compile-only, live
    bug).** `SelectEnemy` compared `BattleEnemyData.Pointer`, but
    `GetEnemyTarget()` returns different wrapper objects for the same enemy,
    so "on the weakest" was never true. Its lap counter was also reset on
    frames where no key was sent (inputs go out every 12th frame), so the
    fallback Confirm never fired. It now matches the native Parameter
    pointer, else monster id + current HP, and changes counters only on send
    frames. **Rule:** any per-press counter must update only when
    `frame % 12 == 0`.

## Stuck detection (all segments, always on)

The user's standing requirement: every movement must be confirmed. It lives
in the shared `Navigation` code, so every navigate step in every route gets
it:
* each frame compares the player's world position with the last one
  (`unchanged` counter);
* within every 90 still frames: frames 12-35 release input so a wandering NPC
  can move away; then it pushes again, and at 90 the path is replanned;
* 600 still frames fails the step ("Movement stalled"), never loops forever;
* modal popups and focus loss reset the counter (not counted as stuck).
Keep this behaviour in any navigation rewrite.

## Segment 2 build (compile-only)

* `Step.BattlePlan`: ordered `BattleRule{character, command, ability, minHpPercent, minMp}`.
  `BattlePilot` picks the first usable rule. It handles AbilitySelect (state 4)
  through `abilityController.selectCursorIndex` and
  `Serial.FF0.UI.KeyInput.BattleQuantityAbilityInfomationController.dataList`,
  learning the grid row stride from the first vertical move. AbilityTargetSelect
  (5) and TargetSelect (6) share `SelectEnemy`. A rule that fails in a battle
  (missing spell, or Confirm doesn't take) is blocked until the next battle.
* Ids: Cecil 1, Rydia 4, Tellah 6. Black Magic 8, Darkness 10 (all enemies,
  HP cost), Recall 28; Thunder ability 39 (5 MP).
* Route `tas/routes/mist-octomammoth.json`: 28 steps. Step-on triggers (Bomb
  Ring, Kaipo arrival, Rosa, waterfall) are navigate-until-Event steps followed
  by mash steps; Tellah and Octomammoth are navigate + interact facing Up.
* `tas.py launch --resume --route <route>`: after a save loads (focused Player
  phase), `auto_step` picks the step from the map id, cell and story flags.
  Steps up to the last set flag are done; steps past the first unset flag are
  unreachable. The plugin now reports ScenarioFlag1 0..40 even while idle.
  `tas.py start --from-step 0` uses the same picker. (A `play` command was
  tried and removed at the user's request.)
* Desktop file `~/Desktop/FF4 TAS Segment 2.desktop` runs `launch --resume`.
* The speed boost is ON at launch (`FF4JOBS_TAS_BOOST=0` disables it); F8 toggles.
  The OnGUI timer overlay was confirmed visible live, so keep it (a uGUI
  rewrite was started and reverted).
