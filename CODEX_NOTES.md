# Notes for Codex: scripted-run (TAS) bugs and changes

Running log kept by Claude while working on the TAS. Newest last. "Live" means
the user ran it in the game. Everything else is compile-only or static
analysis. See also `CLAUDE_HANDOFF.txt` and `docs/TAS-SEGMENT-2.md`.

## Bugs found and fixed (Nov 1 2026)

1. **Stuck on the controls help after the opening (live fixed).** Phase
   `FieldHelp` is the native help/pause window. The opening event ends with
   `ShowHelpAndExit`, which opens it with `FieldHelpManager.IsOpenHelp` set. In
   that mode `UpdateDisplayHelp` ignores Cancel and never reads Confirm; only
   `Key.Start` closes it. The first fix (pulse Back) failed live. The engine now
   pulses Start, then Back (`RouteEngine.Tick`).
2. **Door animations aborted the route (live fixed).** Door opening is the
   SubScene state `Gimmick` (11), which no step allowed. All route steps now
   allow `Gimmick`, and no input is sent during it.
3. **Focus loss killed the run (live fixed).** Focus loss now pauses: input is
   released, step timers freeze, and the run resumes 30 frames after refocus.
   `status.json` shows `paused`.
4. **No path on the overworld (live fixed).** `MapRouteSearcher` returns
   nothing on `map_10010`: its collision group is empty, and walkability
   comes from the `GroundAttribute` grid plus master `transportation_group`
   (row 1 = on foot; attribute N maps to column typeN). Steps now take
   `waypoints`, generated by `tas/plan_path.py`. Navigation also falls back to
   neighbour/closer-cell legs, a final step into trigger tiles, and direct
   steering.
5. **Mist Cave warning picked "No" forever (live fixed).** The `Select` in
   `sc_e_0007` defaults to index 1. Steps take `choice`. The plugin reads
   `MessageSelectWindowManager.Instance.IsOpen()` and
   `controller.selectCursor.Index`, and the engine steers to the option.
6. **Audit y-coordinates were off by one (fixed, tool only).** Tiled tile
   objects (with a `gid`) are anchored at their bottom edge, so cell y is
   `y/16 - 1`. Verified: arrival point 1 = (107,145), matching the live trace.
   Any code that reads entity cells must apply this.

## Features added

* F8 TAS speed boost (default 3x, env `FF4JOBS_TAS_SPEED`). It owns only the
  `timeScale` it set and coexists with the Jobs LT/F6 fast-forward (live OK).
* Run timer: the TAS time is the sum of scaled `deltaTime` (game time), so the
  boost can't shorten it. Wall clock is shown for reference. OnGUI overlay;
  `status.json` has `gameSeconds` and `elapsedSeconds` (live OK).
* Navigation arrival tolerance widens with the observed per-frame stride, for
  boosted movement.
* Tools: `tas/extract_maps.py`, `tas/map_links.py`, `tas/plan_path.py`, `tas/audit_items.py`.

7. **Stuck on the Jobs+ "Job unlocked!" popup (fixed, compile-only).** At flag 7
   Jobs+ opens a CommonPopup over the field during the Player phase and blocks
   `FieldMap.UpdatePlayerStatePlay`. The navigate step only sent directions,
   so it failed as "Movement stalled at (108,106)". The plugin now sets
   `Snapshot.Modal` from `PopupManager.Instance.Filter.activeInHierarchy` (the
   same modal test as Jobs fast-forward), resets navigation while it's up, and
   the engine pulses Confirm for every step kind outside battle. Jobs'
   `MenuInput` reads `InputListener`, so the injected Confirm reaches it.

## Segment 2 build (compile-only)

* `Step.BattlePlan`: ordered `BattleRule{character, command, ability, minHpPercent, minMp}`.
  `BattlePilot` picks the first usable rule. It handles AbilitySelect (state 4)
  through `abilityController.selectCursorIndex` and
  `Serial.FF0.UI.KeyInput.BattleQuantityAbilityInfomationController.dataList`,
  learning the grid row stride from the first vertical move. AbilityTargetSelect
  (5) and TargetSelect (6) share `SelectEnemy`. A rule that fails in a battle
  (missing spell, or Confirm doesn't take) is blocked until the next battle.
* Ids: Cecil 1, Rydia 4, Tellah 6. Black Magic 8, Darkness 10 (all enemies,
  HP cost), Recall 28; Thunder ability 39 (5 MP).
* Route `tas/routes/mist-octomammoth.json`: 28 steps. Step-on triggers (Bomb
  Ring, Kaipo arrival, Rosa, waterfall) are navigate-until-Event steps followed
  by mash steps; Tellah and Octomammoth are navigate + interact facing Up.
* `tas.py launch --resume --route <route>`: after a save loads (focused Player
  phase), `auto_step` picks the step from the map id, cell and story flags.
  Steps up to the last set flag are done; steps past the first unset flag are
  unreachable. The plugin now reports ScenarioFlag1 0..40 even while idle.
  `tas.py start --from-step 0` uses the same picker. (A `play` command was
  tried and removed at the user's request.)
* Desktop file `~/Desktop/FF4 TAS Segment 2.desktop` runs `launch --resume`.
* The speed boost is ON at launch (`FF4JOBS_TAS_BOOST=0` disables it); F8 toggles.
  The OnGUI timer overlay was confirmed visible live, so keep it (a uGUI
  rewrite was started and reverted).

## Known gaps / next work (segment 2)

* **Battle plans:** the pilot only does Attack, Potion, Phoenix Down and Mist
  Dragon Defend. Octomammoth is weak to lightning and dark, so it should do
  Tellah Thunder and Cecil Darkness. Proposed per-step `battlePlan`: an
  ordered rule list per character (command id, spell or item, HP threshold).
  Native command ids: Attack 1, Defend 2, Item 3, Row 5 (not Defend). Jobs
  data names Darkness as command 10 and Black Magic as 8. Verify the native
  ids before relying on them.
* **Menu automation:** nothing yet. Job changes and equipping (Hades gear)
  need a menu driver.
* **"Check" events:** objects with `action_id` 2 (Rosa event at house 37
  (13,9), Tellah at 163 (12,15), waterfall at 170 (13,9)) trigger on Confirm
  while facing them, not on stepping. Use `interact` with `facing`. Doors
  (`GotoMap`) are `action_id` 3, step-on.
* **Camp skip** in Watery Pass is a static-analysis conclusion; confirm the
  native search can cross map 165 without map 166.
* The test suite (`tas/build.sh` without `--build-only`) hasn't been run
  since these changes. `FF4Tas.Tests/Program.cs` now expects focus loss to
  pause, not stop.
