TAS CODE MAP
- tas/FF4Tas.Core/RouteEngine.cs: schema, step validation, observed-frame input
  edges, completion conditions, timeouts, focus stop. New step kinds navigate,
  interact, battle; old hold/wait/mash/checkpoint remain. Completion can check
  phase, map, story flag, destination or optional local visual label.
- tas/FF4Tas.Plugin/Plugin.cs: opt-in/hash gate, Harmony input hooks, frame state
  sampling, request/status protocol, local traces. ActiveStep accounts for the
  pending step transition before the bridge prepares input for the next tick.
- tas/FF4Tas.Plugin/Navigation.cs: reads FieldMap/player; queries native
  MapRouteSearcher.Search with collision enabled. Returned world-space route
  is followed using directional inputs, not position writes. Replans after
  events/encounters or stalls; bounded failure if no progress.
- tas/FF4Tas.Plugin/BattlePilot.cs: reads native KeyInput battle controllers,
  chooses menu directions and Confirm. Attack normally; owned Potion content 2
  or Phoenix Down content 9 when needed. Native command IDs: Attack 1, Defend 2,
  Item 3. Command 5 is Row, NOT Defend.
  Mist Dragon enemy 162, party 223; EnemyCharacterParameter.CurrentMode 1/3
  means mist, 0/2 solid. Uses Defend in mist and cancels unconfirmed attacks.
  Already committed attacks cannot be recalled. Auto-battle or manual pause
  stops the run. Battle tutorial confirmation has a separate handling path.
- tas/tas.py: local launcher/CLI and process-session request protocol.
- tas/routes/baron-mist-dragon.json: 16-step route, current desktop default.
- tas/routes/opening-prototype.json: older short isolation route.
- tas/vision.py: optional local Pillow crop matching, not semantic vision/OCR;
  not used by the default route.

INPUT IMPLEMENTATION / NATIVE PITFALLS
Logical Confirm/Back etc are mapped via native Key names, not physical A/B.
Harmony patches InputListener and KeyConfig GetKey/GetKeyDown/GetKeyUp.
Field movement also patches InputDevice.get_InputAxis (nontrivial unique RVA
0x394750). No raw transform edits, map warps, story flag edits, invented items,
HP manipulation, collision disabling or forced victory.
Do not patch shared IL2CPP trivial getters: many unrelated functions share RVAs.
Avoid generic interface enumerators across IL2CPP; use concrete lists/arrays by
index or dictionary lookup. Jobs previously crashed in equipment enumeration.
Unity/native calls should remain on the main thread with per-frame sampling.
Startup hooks and singleton reads are NOT exonerated by compile success. If
Steam does not resolve the exit, use the new logs before guessing at DLL fixes.
